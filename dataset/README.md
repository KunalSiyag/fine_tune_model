# Website fine-tuning dataset

Training data that teaches a small model to build **distinctive, working,
multi-page websites** instead of the default AI look. You do the
fine-tuning; this folder is everything up to the training file.
Contract: [`SPEC.md`](SPEC.md). Final files: `out/`.

## The core idea in one paragraph

A fine-tune copies the *distribution* of its training outputs. So the
dataset has to be the distribution you want, and nothing else: every
assistant turn is a page we'd put in a portfolio. Volume comes from
**reuse without dilution**: each good page is used several ways (different
prompts, different tasks, and as the "chosen" side of preference pairs).
Generic or broken pages are kept out of SFT completely. They only appear
as the *rejected* side of DPO pairs, so the model learns to move away from
them.

## What's in it (built 2026-10-14)

| source | count | notes |
|---|---|---|
| `corpus/templates/` | 47 pages | your `website_templates/`, bug-fixed copy (29 A-tier, 18 B-tier) |
| `sites/` | 43 sites, 269 pages | 20 from wave 1 + 23 from wave 2 (9 extend unused A-tier templates, 14 designed from scratch with a `DESIGN.md`) |
| `synthetic/` | 290 pages | single pages from sampled design axes (`_queue.jsonl` 60 + `_queue2.jsonl` 120 + `_queue3.jsonl` 50 + `_queue4.jsonl` 60) |
| `external/` | 21 pages | MIT Codrops technique transplants |
| **unique pages** | **627** | every one PASSes `render.py` (`renders/final_v2/`); `slop_check` = 622 keep, 5 review (B-tier templates) |

Wave 2 pages were built against two inspiration libraries researched from
award-gallery sites: `briefs/INSPIRATION_VISUAL.md` (V-01…V-82 layout, type,
colour and page-type patterns + 25 anti-patterns) and
`briefs/INSPIRATION_MOTION.md` (M-01…M-74 motion/interaction patterns +
easing table + 20 anti-patterns). Each page records the IDs it used in an
`inspiration` field (never in the prompt text).

All phones, emails, bank details and domains are obviously fictional (Ofcom
drama ranges, `.example`, sort code 00-00-00, test card 4242…); brands that
collided with real companies in the same field were renamed and the change
recorded in `axis_swaps` / `site.json`.

Wave 3 (`_queue3.jsonl`, syn-181…230) targets gaps measured in waves 1–2:
those were 88% UK-set, all English, none under 20 KiB and only a third dark.
The 50 wave-3 pages are set on six continents with local currency/date
formats; 11 are written in Spanish, Portuguese, French, German, Dutch or
Japanese (their `terse` prompt is in that language too); all are compact
(12–25 KiB); 25 are dark; and 24 use 12 page types the corpus lacked
(status page, privacy policy, search results, settings, receipt, recipe,
listing detail, newsletter archive, lookbook, press kit, store finder,
course syllabus).

Wave 4 (`_queue4.jsonl`, syn-231…290, generated by `pipeline/gen_queue4.py`)
exists to add **short records**. A record costs ≈320 tokens per KiB of page,
so every wave-4 page is 6–14 KiB (median ≈12.7 KiB → 3–5k-token records).
They are formats that are small by nature, not squeezed big pages: 30 micro
pages (link-in-bio, RSVP invite, maintenance page, business card, QR table
menu, one-page CV, gift card…) and 30 single components on a minimal
branded page (booking calendar, command palette, OTP input, kanban, seat
picker, honest cookie consent, audio player…), each with every state,
keyboard support and ARIA. Same global mix: 60 new brands, 10 non-English,
half dark.

`out/` (default build): SFT 1146 train / 114 eval (`page_from_brief` 784,
`site_extend_page` 452, `upgrade` 24); DPO 610 train / 58 eval (`destyled`
339, `off-system` 226, `anchor-nav` 40, `reduced-motion` 39,
`generic-rewrite` 24). SFT train token lengths: 33 records ≤4k, 125 ≤6k,
214 ≤8k, 468 ≤12k, 929 ≤16k; median ≈13k, max ≈23k. Whole-site `site_from_brief` records are all >24k
tokens and are dropped by default.

## Pipeline

```
website_templates/ ──build_corpus──▶ corpus/templates/   (bug-fixed copy: reduced-motion fix)
                                         │
                     extract_design ─────┼──▶ design_systems/*.json   (tokens, fonts, motion vocab)
                                         │
             agents (PROMPTS_AGENT) ─────┼──▶ corpus/prompts/*.json   (instruction back-translation)
                                         │
       agents (SITE_AGENT)   A-tier ─────┼──▶ sites/<site>/           (home + 5–6 new pages, shared css/js)
       agents (SYNTH_AGENT)  briefs ─────┼──▶ synthetic/<slug>/       (new pages from sampled design axes)
                                         │
   make_negatives (auto) + GENERIC_AGENT ┴──▶ pairs/<id>/             (chosen vs one-defect rejected)
                                         │
              render.py + slop_check.py  ──▶ QA gate (PASS required)
                                         │
                         build_dataset.py ──▶ out/sft_*.jsonl, out/dpo_*.jsonl, out/stats.json
```

| Step | Script / brief | What it teaches you about the mechanism |
|---|---|---|
| Normalise | `pipeline/build_corpus.py` | Bugs in training data are *learned*. 41/47 templates hid all content under `prefers-reduced-motion`; fixed in the copy, originals untouched. |
| Hard QA | `pipeline/render.py` | Headless Chrome at 390/820/1440: console errors, failed requests, real horizontal scroll, broken images, invisible-under-reduced-motion. Nothing that fails reaches SFT. |
| Taste QA | `pipeline/slop_check.py`, `tiers.json`, contact sheets | Cheap heuristics catch slop signatures (generic fonts, Tailwind-default palette, purple gradients, buzzwords, emoji icons, centered-hero + 3 cards). Human tiering (A/B) sets sample weights. |
| Design DNA | `pipeline/extract_design.py` | Each template becomes a design system (tokens, fonts, radii, motion vocabulary). This is the conditioning for "make another page *for this site*". |
| Prompts | `briefs/PROMPTS_AGENT.md` | **Instruction back-translation**: we have outputs, so we write the inputs. Three registers per output (`terse` / `brief` / `spec`) so the model works from a one-liner *and* from a detailed spec. Prompts must never claim things the page lacks, or the model learns to ignore instructions. |
| Multi-page | `briefs/SITE_AGENT.md` | Shared `style.css`/`site.js` are frozen; each new page carries its own `<style>`/`<script>`. That makes "add a pricing page to my site" a **single-file answer conditioned on the site**, which is the most useful skill and the cheapest example to make. |
| Diversity | `pipeline/sample_briefs.py`, `briefs/SYNTH_AGENT.md` | Synthetic data collapses to one look unless you force spread. Briefs are least-used-first draws over 8 independent axes (industry, page type, layout archetype, type pair, palette, mode, motion, interaction). |
| Preferences | `pipeline/make_negatives.py`, `briefs/GENERIC_AGENT.md` | A DPO pair should differ in **one** thing. Auto mutations: `destyled` (same page, art direction stripped → taste), `off-system` (consistency), `reduced-motion`, `anchor-nav` (correctness). Agent-written `generic-rewrite` = the real default-AI look. |
| Assemble | `pipeline/build_dataset.py` | Chat-format JSONL, one fixed system prompt, `<file path>` output blocks, **split by source** (all variants of a page go to the same split, so eval isn't leaked), token-length filter. |

## Training tasks in `out/`

| task | input → output | why |
|---|---|---|
| `page_from_brief` | prompt (terse/brief/spec) → `style.css` + `app.js` + `index.html` (+ `assets.json`) | the core skill |
| `site_extend_page` | site context (design brief, shared CSS, chrome, page list) + page prompt → one new `.html` | multi-page consistency |
| `site_from_brief` | prompt → every file of a 6–7 page site | long-horizon; only if it fits `--max-tokens` |
| `upgrade` | generic page + brief → the art-directed page | "fix my boring site" |
| DPO | prompt → chosen vs rejected | moves the model *away* from slop |

Images: when a source has `assets.json`, the model is trained to **emit
`assets.json`** (image prompts) and reference `./assets/<name>`. At inference
you run those prompts through any image model (`pipeline/gen_assets.py`).
Otherwise the prompt lists the available images and the model uses only those.

## Suggested recipe (yours to change)

1. **SFT** (LoRA r=64 or full FT) on `sft_train.jsonl`. Loss on assistant
   tokens only. Use `weight` (B-tier = 0.5) as a per-sample loss weight, or
   just drop B-tier. 2–3 epochs; watch `sft_eval` loss and **render the
   eval generations** with `render.py` + `slop_check.py`. Pass rate and
   slop score matter more than loss.
2. **DPO** on `dpo_train.jsonl` starting from the SFT checkpoint (TRL
   `DPOTrainer` reads this conversational format directly), β≈0.1, 1 epoch.
   Best gains come when you add **on-policy** negatives: sample your SFT model on the
   eval prompts, keep the worst renders as `rejected` (`rejected_kind: on-policy`).
3. Use a base model with **≥24k context** (32k is comfortable). Pages are
   rich: of 1146 SFT train records, 929 fit in 16k tokens and 468 in
   12k. With a 16k model, rebuild with `--max-tokens 16000` (keeps ~81%);
   going lower throws away most of the dataset.

Rebuild everything:
```bash
python3 dataset/pipeline/build_corpus.py
python3 dataset/pipeline/extract_design.py
python3 dataset/pipeline/render.py --glob "dataset/corpus/templates/*/index.html" --out dataset/renders/corpus
python3 dataset/pipeline/render.py --glob "dataset/sites/*/*.html" --out dataset/renders/sites
python3 dataset/pipeline/render.py --glob "dataset/synthetic/*/index.html" --out dataset/renders/synthetic
python3 dataset/pipeline/render.py --glob "dataset/external/*/index.html" --out dataset/renders/external
python3 dataset/pipeline/make_negatives.py   # note: takes no flags; any run regenerates pairs/auto-*
python3 dataset/pipeline/build_dataset.py
```
